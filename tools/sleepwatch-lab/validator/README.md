# SleepWatch 模型实时升级系统

本地闭环工具：**上传图片 → 旧模型检测 → 人工修正 → 确认入库并重训 → 新模型自动生效**。

## 启动

```bash
python \
  validator/app.py
```

浏览器打开：<http://127.0.0.1:8765/>

## 三步使用流程

1. **上传与检测**：拖拽、点击选择或 `Ctrl+V` 粘贴图片，点击「用旧模型检测」。当前生效模型逐张输出预测类别、置信度、`p_asleep` 和识别区域（整图边框）。
2. **人工核对与修正**：表格里「人工确认」默认等于旧模型预测，识别错的改成正确类别；修改行会高亮，页面顶部同步显示旧模型在这批图片上的保真率/准确率/召回率/F1。
3. **确认入库与训练**：点击「确认上传并训练新模型」，人工确认后的图片按标签写入累积数据集，从当前权重续训；页面实时显示 epoch 进度、日志与训练完成后的新阈值和验证指标。新模型写入版本目录后，下一次检测自动使用，无需重启服务。

训练期间仍可继续检测（用旧模型），但不能提交第二个训练任务。刷新页面后若训练未完成，会自动恢复进度轮询。

## 模型升级机制

- 每次升级建立独立版本：`training/live/versions/vN_时间戳/`，内含 `weights/best.pt`、`weights/best.onnx` 和 `meta.json`（阈值、指标、样本数、来源批次）。
- `training/live/current.json` 指向当前生效版本；训练完成后原子更新，Web 服务检测到版本变化即重新加载 ONNX 会话。
- 训练基于当前生效权重续训（YOLOv8n-cls，CPU，15 epoch），验证集自动搜索阈值：优先精确率 ≥ 0.90 且召回率 ≥ 0.40 的候选中 F1 最大者。
- 服务重启后自动恢复到 `current.json` 中的最新版本，不会回退到初始模型。

## 数据与标注位置

```
training/live/
├── pending/<batch_id>/      上传后待确认的图片
├── dataset/{train,val}/     持续累积的 YOLO-cls 数据集
├── versions/                每次升级的权重与指标
├── current.json             当前生效版本
└── annotations.jsonl        每次人工确认的标注记录
```

新图片入库时会自动裁掉插件快照顶部的 46px 黑底文字条（普通照片不受影响），与原始训练数据的预处理保持一致。

## 接口

| 接口 | 说明 |
|---|---|
| `GET /api/info` | 当前版本、阈值、数据集计数、输入规格 |
| `GET /api/versions` | 版本历史 |
| `POST /api/detect` | 上传图片，用当前模型检测并暂存批次 |
| `POST /api/commit` | 提交人工确认标签，入库并启动训练 |
| `GET /api/train/status?job_id=...` | 查询训练状态、进度与日志 |
| `POST /api/validate` | 兼容旧验证器：自带真值标签，直接输出指标 |

## 指标定义（睡着为正类）

- 保真率 / Precision = TP / (TP + FP)
- 准确率 / Accuracy = (TP + TN) / N
- 召回率 / Recall = TP / (TP + FN)
- F1 = 2 × Precision × Recall / (Precision + Recall)
- 误检率 / FPR = FP / (FP + TN)
- 漏检率 / FNR = FN / (FN + TP)

分母为 0 时显示「—」。

## 说明

- 分类模型不输出目标框，因此「检测区域」是整张输入图；缩略图上的边框即为识别区域。最好上传与训练一致的人像裁剪图。
- 当前基线模型召回率仍偏低（验证集睡着样本少），建议持续用本工具补充真实睡着样本，每积累一批就升级一次。
- 该分类器只能作为插件“确认沉睡”阶段的二次校验，不能替代 YOLOv8n-pose 姿态关键点模型。
