生成时间：2026-11-25  
训练环境：Windows / Python 3.13.14 / torch 2.15.0+cpu / ultralytics 8.4.218  
原始相册：**只读**，未做任何修改。

## 1. 数据集

来源：

- `C:\Users\Administrator\Pictures\确认睡觉`：33 张 JPG
- `C:\Users\Administrator\Pictures\确认未睡觉`：399 张 JPG（另有 1 个 `desktop.ini`，已忽略）

这些都是插件生成的“人体框局部裁剪图”（宽 320px，高度可变）。顶部有 46px 黑底文字条，内容是课程、编号、时间、置信度。训练前统一裁掉该文字条，避免模型学到时间/编号等无关信息。

划分（固定随机种子 42，每类独立分层）：

| 用途 | asleep | awake |
| --- | ---: | ---: |
| 训练集 | 26 | 319 |
| 验证集 | 7 | 80 |

## 2. 两轮训练对比

预训练权重：`yolov8n-cls.pt`，模型为 YOLOv8n-cls（1.44M 参数，3.3 GFLOPs）。输入 224×224，batch 16，CPU 训练，早停 patience=15。

| 实验 | 训练类别分布 | top1 准确率 | 睡着精确率 | 睡着召回率 | 睡着 F1 | 睡着混淆矩阵 (TP/FP/FN/TN) |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| A 原始比例 | 26 / 319 | 0.931 | 0.667 | 0.286 | 0.400 | 2 / 1 / 5 / 79 |
| **B 平衡过采样（推荐）** | 208 / 208 | **0.943** | **1.000** | 0.286 | **0.444** | **2 / 0 / 5 / 80** |

平衡做法：把 26 张 asleep 原图各生成 7 个轻量增强版本（水平翻转、亮度 ±12%、对比度 +15%、旋转 ±4°）得到 208 张；从 319 张 awake 中随机抽 208 张。验证集完全不变，便于公平对比。

**结论**：平衡训练把“睡着”精确率从 66.7% 提到 100%，误报从 1 降到 0，整体准确率从 93.1% 提到 94.25%；但召回率没有改善，7 张睡着验证图仍只识别出 2 张。

## 3. 推荐模型与决策阈值

- 权重：`sleepwatch_cls_balanced.pt` / `sleepwatch_cls_balanced.onnx`
- 类别顺序：`0 = asleep`，`1 = awake`
- 推荐阈值：`p_asleep >= 0.42` 判为睡着（0.50 结果完全相同）
- 阈值扫描结论：在 0.05～0.95 之间没有任何阈值能同时做到高精确率和高召回率。降到 0.05 时 TP=3、FP=9，精确率跌到 25%。所以**不要为了召回率盲目降低阈值**。

## 4. ONNX 规格

| 项目 | 值 |
| --- | --- |
| 输入名 | `images` |
| 输入形状 | `[1, 3, 224, 224]`（导出为动态维度，建议固定 1×3×224×224） |
| 输入格式 | RGB，NCHW，像素值 0～1 |
| 输出名 | `output0` |
| 输出形状 | `[1, 2]`，未归一化 logits；做 softmax 后取第 0 维为 `p_asleep` |
| 预处理 | 按短边等比缩放到 224 → 中心裁剪 224×224 → RGB → /255 → HWC 转 CHW |
| 归一化 | mean=(0,0,0)，std=(1,1,1)，即无需额外归一化 |

## 5. 接入 SleepWatch 插件的建议

这个二分类模型**不能替代**现有的 `yolov8n-pose` 姿态关键点模型：姿态模型负责找人、17 关键点、轨迹和计时；分类器只能判断一张已经裁好的人像“像不像睡着”。建议把它作为**确认沉睡阶段的二次校验**，用于降低误报：

1. `PoseDetector` / `DetectionEngine` 照旧输出每个人的 bbox、关键点和静置计时。
2. 当静置时长达到“沉睡确认”条件时，先不要立即写 `history.json`、抓快照、计入主界面数字。
3. 从当前帧按该人的 bbox 裁出人像（若用证据快照图，必须先裁掉顶部 46px 文字条），按第 4 节预处理后送 ONNX。
4. 仅当 `p_asleep >= 0.42` 才确认为沉睡；否则保持“疑似”，继续计时或回到清醒。
5. 阈值写进 `settings.json`，默认 0.42，让用户可调。

注意：当前召回率只有 28.6%。如果把它设为**强制门槛**，真实睡着事件会有约 7 成被拦下。更稳妥的用法是：姿态模型已判定确认沉睡、且分类器给出 `p_asleep >= 0.42` 时立即确认；分类器不确定时延长确认时间而不是直接丢弃，同时把置信度写进日志便于后续收集难例。

## 6. 局限与下一步

- 睡着样本只有 33 张，验证集只有 7 张，所有指标波动都很大；100% 精确率不等于真实场景不会误报。
- 部分 `确认未睡觉` 样本视觉上头靠手、姿势接近趴桌，标签本身可能存在噪声。
- 想真正提高插件识别质量，最有效的是继续积累**睡着**样本（目标每类至少 200～500 张真实裁剪图），或者为 YOLOv8n-pose 补 17 关键点标注后续训姿态模型。
- 若要替换姿态模型，必须有关键点标注；仅靠睡/醒文件夹无法训练 YOLOv8-pose。
